# /handoff: clean-context session handoff

Hand the current session to a clean context with zero info loss. Native `/compact` is lossy, so the plugin's `PreCompact` hook lets a compaction through only after you have saved the working state with `spawn:"compact"`; after the compaction the `SessionStart` hook re-seeds you from that document, which outranks the summary. The `Stop` guard makes sure the save happens: above the save threshold it blocks the end of your turn until the state is saved.

When invoked:

1. **Author the working state** as JSON with exactly these keys (lists may be empty, but every key is required): `goal` (one sentence), `specifics` (files/symbols/branch/PR/URLs in play), `state` (what's done, past tense), `nextStep` (the ONE next action), `constraints`, `gotchas`, `openQuestions`, `keepOnFail` (irreducible facts), `verify` (exact build/lint/test commands). Optional `title`: the session topic in 2-4 words (defaults to the previous handoff's title, else the first words of `goal`). `spawn`: `"compact"` (the automatic path: save under `.claude/handoff/auto/<session id>/`, let auto-compaction reset the context, continue) | `"clear"` (the manual path: save, then the user types `/clear` and this same session resumes) | `"same-window"` | `"window"` | `"terminal"` | `"none"` | the legacy `"uri-target"`. Optional `transcriptPath` (compact only): the session transcript, so the marker records `tokensAtSave`; defaults to `CLAUDE_CODE_TRANSCRIPT_PATH`. Optional `callerCwd`: the CURRENT window's workspace root (defaults to `process.cwd()`; pass it explicitly when you have already run `EnterWorktree`, since the session's cwd is then the worktree, not the window folder). Reflect honestly on THIS conversation; be concrete.
2. **Refuse** if you cannot fill `goal` and `nextStep`: ask the user instead.
3. **Pick the spawn mode**: `"spawn":"compact"` when the Stop guard, the PostToolUse nudge or the PreCompact refusal asked you to save or refresh the state (the user typed nothing; do not ask). `"spawn":"clear"` when the user invoked `/handoff`. A spawning mode (`same-window`, `window`, `terminal`) only when the user asked for a new tab, window or terminal; never ask otherwise. (The glue's own default is still `same-window` for programmatic callers, so the field must be explicit.)
4. **Run the glue once**, piping the JSON to it (use a heredoc):

   ```bash
   node "${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/skills/handoff}/tools/handoff.cjs" <<'JSON'
   {"spawn":"compact","title":"panel verdicts","goal":"...","specifics":["..."],"state":"...","nextStep":"...","constraints":["..."],"gotchas":["..."],"openQuestions":["..."],"keepOnFail":["..."],"verify":["..."],"callerCwd":"/path/to/current/window/root"}
   JSON
   ```

   `callerCwd` is set to the workspace root of the CURRENT window, not the target project the handoff is about.

   CLAUDE_PLUGIN_ROOT is set when the skill runs as a plugin; the default covers a copy in the user skills directory. If the skill lives elsewhere, substitute the directory containing this SKILL.md.

   With `spawn:"compact"` the result carries `spawn.mode === "compact"` and a `message`: **relay that message verbatim** ("State saved to <doc>. Compaction will reset the context; continue.") and go on with your work. Nothing is spawned, no registry entry is written, nothing to close, nothing for the user to type. Auto-compaction passes the `PreCompact` interlock now; afterwards the `SessionStart` hook re-seeds you from `.claude/handoff/auto/<session id>/HANDOFF.md`, which is authoritative over the summary, and you continue from its Next step within the authorization you already had. If the Stop guard later says the snapshot is stale (more than `HANDOFF_STALE_TOKENS`, default 40000, since the save), run the glue again with fresh fields. Skip steps 5 and 6.

   With `spawn:"clear"` the result carries `spawn.mode === "clear"` and a `message`: **relay that message verbatim** ("State saved to <doc>. Type /clear; I will continue from Next step.") and stop. Nothing is spawned, no registry entry is written, nothing needs closing. When the user types `/clear`, the `SessionStart` hook (source `clear`) reads the marker, injects the pointer and sends the first message, and the same session continues from `HANDOFF.md`. Skip steps 5 and 6.

   For the other modes the result carries `title` (e.g. `panel verdicts #3`), `generation`, `mode`, `sessionNamePrefix` (e.g. `agent-test-`) and `resumeMessage`.
5. If your Claude Code exposes the ListAgents and SendMessage tools: **Wake the fresh session** (extension and CLI alike; skip only when `spawn.mode` is `manual`):
   1. Wait about 15 s (`sleep 15`), then call `ListAgents` once. The fresh session is the row whose name starts with `sessionNamePrefix` and whose "started" age is the youngest (well under a minute). Confirm it before messaging: a transcript created after the spawn time must exist (`find ~/.claude/projects -maxdepth 2 -name '*.jsonl' -newermt '<spawn HH:MM:SS>'`; on Windows use Git Bash or skip this check) and its first message must start with the tab title. A row that is merely young can be one of the user's own tabs (observed 2026-09-02: a resume message went to a live user session by that mistake).
   2. `SendMessage` to that name with `message` = `resumeMessage` and `notify_when_idle: true`. A fresh session processes a cross-session message with no typing from the user (verified 2026-09-02: an idle tab with an unsubmitted prompt replied within seconds).
   3. If no such row appears, retry the listing once after another 15 s. If the youngest new row carries ANOTHER project's prefix, the tab landed in the window the user was clicking in: tell the user to close that tab without submitting its prompt (the prompt names the project root, so a submitted one stops itself). Then hand the work over anyway: either an idle session with the right prefix (an unused tab in the project window) gets the `resumeMessage` and you consume the marker by renaming `handoff.pending.json` to `handoff.consumed.json`, or the user opens a new tab in the project window and the SessionStart hook resumes it.
6. **Relay** the result, then tell the user: **"Handoff is ready in the fresh session `<title>`, close this one to finish."** (Closing the old session is the one manual step; nothing can close it automatically.) The idle notice from the fresh session arrives later on its own; do not poll for it.

Resume is automatic: the fresh session's `SessionStart` hook injects a pointer and auto-sends the first message. The URI prompt is a backstop for when the hook is unavailable; both start with the tab title.

**The automatic path is the default because nobody has to type anything.** The `Stop` guard blocks the end of a turn above `150000` tokens until a fresh `resumeMode:"compact"` marker exists for this session and compaction epoch (two blocks per epoch at most, then it fails open). The snapshot lives under `.claude/handoff/auto/<session id>/`, so two sessions in one repository never overwrite each other, and the marker records `tokensAtSave`, so a save at 150k that is 40k tokens old is no longer trusted: the guard and the interlock ask for a refresh instead. Keep the driving session thin (bulk-read, delegate to workers): the reset is the safety net, not the plan. `/clear` is the manual fallback: it keeps the session id and transcript, so the marker written with `resumeMode:"clear"` is consumed only by a `SessionStart` with `source:"clear"`; a startup, fork, compaction or another tab in the same project leaves it alone. Its pointer says "same session, context was cleared"; the first message names `.claude/handoff/HANDOFF.md`.

**Among the spawning modes, same-window is the default, so there is nothing to stay put for.** The URI fires immediately, with no focus step and no delay, so it lands in whichever window you were already talking to; the new session starts there (`callerCwd`), not in the target project. That is why its first message tells it to `EnterWorktree` (with `path`, never `name`) into the target root before reading `HANDOFF.md`, and why the "wrong window" check accepts either `callerCwd` or `targetCwd` as correct. Ask for `spawn:"window"` or `spawn:"terminal"` only when the user asks for a separate window or a terminal; a genuinely parallel handoff (two spawns within about 20 s) can still land in the wrong tab, since spawns are not queued.

Same-window still works when the current window's folder is not a git repository (`EnterWorktree` needs one): the message instead tells the fresh session to work on absolute paths under the target root, `cd`-ing into it for every shell command instead of entering a worktree.

**First-time setup:** none when installed as a plugin. The plugin install wires all four hooks (the `SessionStart` resume hook, the `PostToolUse` tripwire, the `Stop` guard and the `PreCompact` interlock) through `hooks/hooks.json`; restart Claude Code once after installing so they activate. Recommended: `"autoCompactWindow": 200000` in `~/.claude/settings.json` (and `HANDOFF_AUTOCOMPACT_WINDOW=200000` in the environment), so the save threshold sits at or below 0.75 × the window; the Stop guard warns on stderr when it does not. Run `node "${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/skills/handoff}/tools/install.cjs"` only when you installed by copying this directory into `~/.claude/skills` and the hooks do not fire: it merges both hooks into `~/.claude/settings.json` (secret-safe, idempotent, preserves existing hooks), then restart Claude Code.

## Session naming
- Tabs are titled after their first prompt unless a custom title exists. A handed-off session is therefore named `<title> #<generation>` automatically: the hook puts it at the front of the first message and writes the custom-title sidecar next to the transcript.
- To name the CURRENT session once its topic is clear: `node "${CLAUDE_PLUGIN_ROOT:-$HOME/.claude/skills/handoff}/tools/session-title.cjs" "<topic in 2-4 words>"` (reads `CLAUDE_CODE_SESSION_ID`, writes the sidecar only, never touches the transcript). The open tab may keep its old label until it is reopened; the session picker shows the new one. Do not append `#n` by hand: the handoff glue owns the generation counter.

## How it works
- `tools/handoff.cjs` captures the 9 fields (+ title), redacts secrets, writes `.claude/handoff/HANDOFF.md` (frontmatter carries `title` and `generation`, bumped from the previous doc) plus an atomic single-shot marker in the TARGET project, then dispatches `tools/spawn-tab.cjs` per the chosen mode and, for every mode but `none` and `clear`, writes a registry entry under `~/.claude/handoff/pending/` so the hook can find the marker even from a different window. In `clear` mode the marker also carries `resumeMode:"clear"` and the session id from `CLAUDE_CODE_SESSION_ID`. In `compact` mode the document and marker go to `.claude/handoff/auto/<session id>/` instead, and the marker carries `resumeMode:"compact"`, the session id, the compaction epoch (from `.context-baseline.<session id>.json`, else 0) and `tokensAtSave` (newest usage line of the transcript, else 0).
- `tools/spawn-tab.cjs` runs every editor launch WITHOUT `ELECTRON_RUN_AS_NODE`: a session started by the Cursor extension inherits that variable, and with it the editor binary boots as plain node and rejects `--open-url`, so the URI used to be a silent no-op (root cause found 2026-09-02).
- `hooks/sessionstart-handoff.cjs` runs on every session start and reads `startup_reason`, falling back to `source`. On `clear` and `compact` it first writes `.claude/handoff/.context-baseline.<session id>.json` (epoch + 1, current transcript byte length) so the hooks ignore usage lines older than the reset. On `compact` it then looks only at `auto/<session id>/`: a marker owned by this session and within its TTL is re-seeded (pointer: the summary above is lossy, the document is authoritative, read it now, continue from Next step within the authorization you already had) and consumed; any other marker is left alone. Otherwise it checks for a local pending marker at this cwd: a `resumeMode:"clear"` marker is consumed only on `source:"clear"`; a legacy marker (the `window`/`terminal`/`uri-target` case) on any source. If none, and the session just started, it scans the registry for an entry matching this cwd as either `callerCwd` or `targetCwd` (the `same-window` case), sweeping stale or invalid entries as it goes. Either way it injects the pointer, auto-sends the resume message, names the tab, and consumes the marker (so normal sessions are untouched and it never re-fires).
- `hooks/usage-monitor.cjs` (`PostToolUse` auto-trigger) evaluates two independent signals and injects an `additionalContext` nudge when one crosses a threshold: the 5-hour rate limit (`rate_limits.five_hour.used_percentage` from the payload) and the context size (the newest assistant `usage` line in `transcript_path`: `input_tokens + cache_creation_input_tokens + cache_read_input_tokens`, read from the tail with a growing window capped at 4 MB, skipping sidechain lines and other sessions). It is a **tripwire, not a capture**: a `PostToolUse` hook can't author the working state, so it asks the agent to. Each signal fires each level at most once per session and epoch (`.claude/handoff/.last-warned.<session id>.json`). Every call also appends the reading to `.claude/handoff/context-log.ndjson` (`ts, sid, epoch, offset, tokens, cacheRead, cacheCreation, event`, one line per new transcript offset, 5 MB cap).
- `hooks/stop-context-guard.cjs` (`Stop`) reads the same context size at the end of a turn. Above the save threshold with no fresh compact snapshot for this session and epoch it answers `{"decision":"block","reason":...}` naming the token count and the save instruction (or a refresh when the snapshot is more than `HANDOFF_STALE_TOKENS` old). Two blocks per session and epoch (`.claude/handoff/.stop-deny.<session id>.json`, 45 s floor), then fail-open; honours `stop_hook_active`; ignores other events, sidechain usage, a missing transcript and malformed input.
- `hooks/precompact-guard.cjs` (`PreCompact`) exits 0 for `auto` and `manual` compaction when a fresh compact snapshot exists for this session and epoch (or `HANDOFF_ALLOW_COMPACT=1`); otherwise exits 2 with the save/refresh instruction on stderr (the `/clear` manual fallback included). Two refusals per epoch (`.compact-deny.<session id>.json`); the third appends `fallback:native-compaction` to the context log and passes. Malformed input exits 0.

## Auto-trigger (enabled by default)
- **Rate-limit thresholds:** `90%` gentle nudge; `95%` urgent nudge. Retune or disable via `HANDOFF_AUTO_SAVE_PERCENT` and `HANDOFF_URGENT_PERCENT` (a number such as `85`, or `disabled`). `rate_limits` is exposed to hook stdin only on newer Claude Code for Pro/Max; where it's absent that signal silently no-ops.
- **Context thresholds:** `150000` tokens save (the Stop guard blocks, the tripwire nudges: run the glue with `spawn:"compact"`); `180000` urgent nudge. Retune or disable via `HANDOFF_CONTEXT_SAVE_TOKENS` and `HANDOFF_CONTEXT_URGENT_TOKENS`. `HANDOFF_STALE_TOKENS` (default `40000`) is how far past `tokensAtSave` a snapshot still counts as fresh. `HANDOFF_AUTOCOMPACT_WINDOW` mirrors your `autoCompactWindow` so the Stop guard can warn when the save threshold exceeds 0.75 × it. Where `transcript_path` is missing or unreadable the signals silently no-op.
- **Compaction:** `HANDOFF_ALLOW_COMPACT=1` disables the `PreCompact` interlock for that session. Recommended: `"autoCompactWindow": 200000` in `~/.claude/settings.json` (the plugin never writes it).
- **Single-shot** per session, signal, level and epoch (no per-tool-call spam); after `/clear` or a compaction the context signal re-arms for usage written after the reset.
- **Defensive:** every hook is fail-open; the monitor never blocks a tool call.
- **Nudge-only by design:** at the urgent level it still only nudges (it does not auto-author a degraded handoff). Durable memory is the independent safety net, and a real handoff stays agent-authored and high-fidelity.

## Notes
- Path anchor is **cwd to nearest `.git`** (never `CLAUDE_PROJECT_DIR`), so the write-path and read-path can't diverge.
- Secrets (DB URLs with passwords, API keys, tokens) are redacted before any write.
- The handoff doc is your own prior notes: verify against the live repo before destructive actions; the skill never auto-runs its `verify`/`nextStep` commands.
- Env knobs: `HANDOFF_CONTEXT_SAVE_TOKENS`, `HANDOFF_CONTEXT_URGENT_TOKENS`, `HANDOFF_STALE_TOKENS`, `HANDOFF_AUTOCOMPACT_WINDOW`, `HANDOFF_ALLOW_COMPACT` (see Auto-trigger), `HANDOFF_SPAWN` (`compact` | `clear` | `same-window` | `window` | `terminal` | `none` | `uri-target`, legacy `auto`/`uri` map to `uri-target`), `HANDOFF_URI_SCHEME` (default `cursor`), `HANDOFF_EDITOR_EXE` (editor binary used to focus or open the project window), `HANDOFF_TERMINAL_EXE` (terminal binary for `terminal` mode, default `wt.exe` from WindowsApps when present), `HANDOFF_HOME` (registry root, default `~/.claude/handoff`).
- A stale pending marker is consumed by the NEXT session that starts in that project, whoever opens it. If a spawn ever fails, the next tab you open there will resume the handoff.
- Two handoffs fired within about 20 s of each other can still land in the wrong tab: spawns are not queued.
